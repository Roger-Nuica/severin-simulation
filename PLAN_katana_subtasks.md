# Plan: Katana (directional alien slicing) — implementation subtasks

Source brief: `PLAN_katana.md` (unchanged; this file decomposes it). Written by the Lead role (`.claude/agents/lead.md`) under `full-autonomous-run` Phase 1 and `coder-plan-run`. No production code is written by this plan.

## Goal

Add a sixth Hero Mode weapon, the Katana: a no-energy melee weapon that cuts aliens only, with Quick Slash (swipe or click combo) and Blade Mode (hold click, slow world, draw a cut line, up to 3 cuts). A cut clones the alien, clips each half with opposite sides of a plane, caps the cut face, and turns each half into a simple physics piece that fades. Everything must reuse the existing weapon wheel, enemy registry, scoring/combo, time-hold, particle-pool and sound paths, and must stay inside the existing caps and the 400 draw-call budget.

## Findings from reading the repository

### Source-of-truth checks (runtime code versus `.claude/rules.md`)

Verified as consistent with runtime (no action): R-026 combo (window 2.5 s, +0.15 per link, +3 cap; `gamefeel.js:43-48`); R-029 Bullet Time 3 %; R-032 Time Slow 30 % (`player/abilities.js` `ABILITIES.timeSlow`: `scale 0.3`, `bulletScale 0.03`); R-048 caps (`perf/caps.js`: 160 enemies, 50 clones, 10,000 particles); R-049 current wheel order (`heroWeapons.js:52`: `rifle, minigun, railgun, fire, blackhole`).

Conflicts, gaps and hazards on systems this task would modify:

1. **R-049 wheel order will be extended.** The brief explicitly asks for the Katana on the wheel. Recorded as an **explicit, user-approved extension**: `katana` is appended as the sixth entry, so the order of the existing five is unchanged. Text that says "five weapons" must be updated in Subtask 15: `heroWeapons.js` header, `hero/input.js` header, `docs/weapons.md`, `GAME_DESIGN.md` line 61, `.claude/skills/hero-weapons-combo/SKILL.md`, R-049 itself.
2. **Blade Mode 10 % slow versus the existing slow states.** `time.js` resolves holds by the lowest scale per group, and `gamefeel.js updateGameFeel` caps `timeScale` by `forcedScale` with `Math.min`. Existing world scales: Time Slow 0.3 (R-032), Bullet Time 0.03 (R-029), GameFeel combo slow-motion 0.3 (`SLOWMO_SCALE`, not in rules.md), Action Hero 0.35 (`actionHero.js AH.slowmo`). Blade Mode as `time.hold('bladeMode','world',0.1)` therefore wins over all of them except Bullet Time (0.03), which stays lower; releasing Blade Mode must release only its own hold id. Blade Mode must not reuse `Post.bulletTime` (it also drifts the camera, `hero/screen.js:207`, and muffles audio).
3. **`time.js` states a rule that the brief breaks.** The header says "slowing the world never slows the player", and the `player` group has no consumer anywhere (`grep scale('player')` finds nothing; `updateHero` runs on `rawDt`). The brief asks for the player to be "slowed less". See open question Q3. Default proposed: Roger is not slowed (the cut line runs on real time anyway); no change to `time.js` semantics.
4. **T-Rex accepts `blade`.** `trex.js:383` lists `blade` in `accepts`, because samurai kill the T-Rex (R-020). The brief wants the T-Rex to parry the Katana. Therefore the Katana must not send a `blade` hit through `enemies.hit()` to non-alien kinds. The Katana filters on `kind.kind === 'alien'` itself and plays the parry for every other registered kind. No existing `accepts` list is changed.
5. **Alien owner contract needs an additive extension.** `aliens.js:297-306` handles `blade` with `slashKill` (samurai), which burns the alien with `slain` for the burning timing and scores `ALIENS.killScore` once inside `crew.js ignite()`. The Katana needs a different outcome (alien removed, pieces spawned). That requires an additive owner-side hook (a `sliceKill` beside `slashKill`). Under R-050 this needs the user's approval before editing (open question Q5). Note `ignite()` already scores the kill and plays `alienDeath`, so the Katana must not score the base kill a second time (R-026, R-027).
6. **Aliens are drawn by the instancer.** `environment/instancer.js` hides an alien's own meshes and draws it as instances while `skin.emissive` equals `ALIEN_SKIN_GLOW`. A naive `root.clone()` copies `visible = false`. The clone path must force visibility and use cloned materials (R-048, hot-path rule).
7. **Draw-call budget.** `perf/budget.js` allows 400 draw calls (FINDINGS "Performance budget"; heavy scenario measures 252, leaving about 148). An alien is 12 meshes (2 legs, torso, 2 arms, gun body, barrel, emitter, neck, head, 2 eyes; 15 with the second wave's sombrero). Cloning it per piece costs about 12 to 15 draws per piece, so 60 pieces would be about 720 to 900 draws: **the brief's 60-piece cap cannot fit as specified.** See "Brief numbers that do not fit" below.
8. **`GAME_RULES.md` does not exist.** The brief says to update it. Rules live in `.claude/rules.md` (Romanian, R-001 to R-050) and `GAME_DESIGN.md` (English). See open question Q8.
9. **Docs language.** The global instruction requires British English in documentation; `.claude/rules.md` is in Romanian. See Q9.
10. **Right-click currently means first-person aim.** `hero/plasma.js toggleAim/enterAim` switches the phase to `aiming`, hides Roger, locks the pointer. The brief wants the Katana visible in third person. The Katana therefore needs its own "drawn" state that does not enter `aiming` (Subtask 2). `S.state.drawn` is also read by `hero/movement.js poseRoger` to choose the rifle arm pose, so it needs a Katana branch.
11. **Hit-stop does not exist.** The brief asks for 3 to 5 frames. There is no frame-based hit-stop in the engine. It will be implemented as a short real-time world hold (about 50 to 80 ms, frame-rate independent). See Q7.
12. **"Aliens in a ship crew".** Aliens inside the UFO (`phase 'aboard'`) are not in the scene and cannot be cut. The cuttable phases proposed are `patrol`, `escort`, `exiting` (the same set `slashKill` accepts). See Q6.
13. **Combo event classes.** `gamefeel.js EVENTS` decides what extends a chain (HWC). The Katana needs one new, additive event entry; it must not make every hit a combo event.
14. **`caps.trackPool()` has no untrack.** A goo pool created per run would leave stale references in `caps.js`. The goo pool should be created once per simulation (Subtask 8).
